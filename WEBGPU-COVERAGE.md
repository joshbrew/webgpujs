# WebGPUjs coverage

Looking up `f32()`, `distance()`, `threadId` or another shader name? Start with [Shader names, types and built-ins](docs/SHADER-LANGUAGE.md), including the complete official function directory and the wrapper's stage aliases.

The wrapper covers the core WebGPU compute/render workflow, with JavaScript shader generation and native WGSL/descriptor interoperability. This table distinguishes **automatic wrapper support**, **tested native integration**, and work deliberately left to the application. It does not imply that every optional feature exists on every adapter.

Reference scope: [WebGPU interfaces](https://developer.mozilla.org/en-US/docs/Web/API/WebGPU_API#interfaces), [WGSL](https://www.w3.org/TR/WGSL/), and the actual regression suites: [pipeline/example tests](tests/gpu.test.js), [feature tests](tests/gpu-features.test.js), [parser tests](tests/parser.test.js), and the [browser VideoFrame check](tests/browser-external.html).

## Deliberate boundaries

- General JS objects, arbitrary closures, dynamic local arrays, promises and browser APIs inside shaders do not become WGSL. Use the supported JS subset or native WGSL.
- Arbitrary nested uniform/storage structures and unusual packing are native data-layout concerns. Supply packed GPUBuffer bindings rather than infer application object layouts. Ordinary scalar/vector/matrix layouts and numeric storage padding are automatic.
- Optional/extension-specific features, experimental binding arrays, subgroups and format capabilities depend on the browser/device. Use native WGSL/feature requests and explicit bindings for those paths; no blanket portability claim is made.
- Automatic MSAA targets follow the canvas. Complex offscreen attachment graphs, custom resolves, compressed copies, query allocation and video lifetime remain explicit native descriptors/commands. The wrapper can compose with them without replacing the native API.

The boundary is intentionally a transpiler plus resource/pipeline convenience layer. Native device, buffer, texture, layout and command encoder handles remain usable; a second wrapper API for every WebGPU object is unnecessary.

Lifecycle regressions cover partial-build cleanup, storage/geometry replacement, linked and independent resource consumers, shared depth, queued chain disposal, staging transfer, listener removal and default-device loss/recreation. [Browser/backend checks](docs/COMPATIBILITY.md) distinguish executed results from planned CI coverage.
